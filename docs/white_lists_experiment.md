# White Lists Experiment — Brew Adaptive Network

## Цель

Экспериментальная ветка для улучшения устойчивости подключения в сетях с нестабильным доступом. Изменения должны помогать диагностировать, восстанавливать и измерять соединение, не подменяя конфигурацию провайдера и не меняя ядро без необходимости.

## Что добавлено в интерфейс

- Раздел навигации **Прокси** вместо общего названия «Узлы».
- Карточка обзора прокси: количество узлов и групп, активная группа и быстрый переход в диагностику.
- **Brew Network Lab** — единая точка проверки доступности серверов, задержки Mihomo, текущего маршрута и активных соединений.
- Диагностика явно показывает ограничения измерений: открытый TCP-порт не доказывает, что сам протокол работает, а успешная задержка не гарантирует доступность всех сайтов.

## Следующие этапы эксперимента

1. Разделить результаты на DNS, доступность сервера, запуск ядра, состояние туннеля и доступ к контрольному HTTPS-адресу через выбранный прокси.
2. Добавить историю проверок и краткую подсказку по вероятному этапу сбоя.
3. Добавить ограниченное восстановление соединения с паузами и защитой от бесконечных циклов.
4. Перед автоматическим переключением узлов проверять результат штатными средствами Mihomo и сохранять выбор пользователя.
5. Добавить тесты для Android и Windows, а также проверку сборки в GitHub Actions.

## Границы текущей реализации

Сейчас Brew Network Lab использует уже существующие проверки Mihomo и TCP-доступности. Это первая итерация интерфейса и диагностики, а не готовая система автоматического обхода фильтрации. Не следует объявлять сетевую проверку успешной только потому, что сервер отвечает на TCP-порт. Ядро, VPNService и настройки провайдера в этой итерации не переписываются.
